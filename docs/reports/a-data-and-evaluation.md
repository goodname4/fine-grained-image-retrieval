# A：数据构建与评测方法章节

本章是课程报告的数据与评测部分初稿。数据清洗和工具验证已有实际产物，模型效果部分待B/C真实运行后填写。机器可读证据见[flickr8k-v1-verification.json](flickr8k-v1-verification.json)。

## 数据来源

采用Hodosh、Young、Hockenmaier的Flickr8k。用途依据来自[原作者项目页](https://hockenmaier.cs.illinois.edu/Framing_Image_Description/KCCA.html)：提供给非商业研究和教育，原作者不拥有全部图片版权，使用者仍须遵守Flickr条款。本项目本地用于课程，不在Git中再发布图片或完整数据。

实际获取自[jbrownlee公开release镜像](https://github.com/jbrownlee/Datasets/releases/tag/Flickr8k)，该地址也出现在[Keras官方示例](https://keras.io/examples/vision/image_captioning/)。镜像存在不代表额外授权，下载ZIP的SHA-256保存在`configs/data/flickr8k-source.json`。解压后的readme明确说明train/dev/test文件对应原论文划分。

引用：M. Hodosh, P. Young, J. Hockenmaier. *Framing Image Description as a Ranking Task: Data, Models and Evaluation Metrics*. Journal of Artificial Intelligence Research, 47:853–899, 2013.

## 原始版本核对与清洗

镜像实际解出8091张JPEG，token描述涉及8092个图片文件名，官方划分列出8000张；92张描述图片不在划分中。选中8000张均存在且通过Pillow文件验证及完整解码。因此包与描述总数差异未导致实验样本缺失，不能用ZIP图片总数替代实际规模。

按图片保留官方6000/1000/1000划分，每图5条描述，不把同图描述拆入不同集合。检查全局ID、安全相对路径、重复路径、文件SHA-256及解码RGB像素SHA-256；以EXIF方向校正后的64位dHash、Hamming距离≤8生成近重复候选，再逐对看图。

得到21对候选，其中10对跨集合。辅助看图结论为1对完全相同、2对同场景相近帧、18对误报；跨集合10对中仅1对为同场景近重复。dHash可能漏掉裁剪、构图变换等情况，检查通过不能证明完全无泄漏。

| --- | --- | --- |
| 排除训练记录 | `2851198725_37b6027625` | 与训练图`3050606344_af711c726c`文件及像素相同；保留列表中较早记录 |
| 排除训练记录 | `475313618_bdb2f72be5` | 与验证图`475317104_1cdc1653b4`是同一人物/背景的相近帧；保留验证图 |

两张被排除图的各5条描述一并退出训练，未转移给保留图片。原始清单不修改，排除理由、原始摘要、辅助看图记录与清洗清单分别保存；所有方法共同使用清洗版。

长度按空白切词，不是CLIP tokenizer长度，没有据此截断文本。宽度范围164–500、高度127–500像素。清洗后没有检查器识别的字节或解码像素完全重复，保留的dHash候选均有辅助看图记录。

描述小写化及空白归一后，207种文本重复，其中82种跨划分重复。通用描述重复不自动等于图片泄漏，未机械删除；它提示不同图片可能共享有效描述，源图配对之外的相关性并不完备。完整重复文本清单仅保存在本地统计输出。

## 隔离训练与测试

训练输入仅从train展开，query_id为`image_id#描述编号`。默认辅助读取器每epoch每图选一条，连续5个epoch轮转全部描述，固定种子与顺序。C若使用全部描述，需实施多正样本mask；同场景组提示防止假负样本，不保证任意跨帧描述均相关。

val用于选模型、早停和超参数；test不参与训练、挖掘或调参。val/test各1000图候选和5000描述查询，候选、查询、qrels及清单摘要绑定为协议。遗漏查询、未知图片、重复结果、深度不符或摘要失配均报错。

## 细粒度标注

固定seed42从test筛选100张不同源图，每个主类别25条、A/B/C/D各25条，A/B与C/D互审。自动词汇规则只是筛选，号码six不等于六个主体，through the air未必是主体之间的关系。

A的25条已逐图完成AI辅助初标，在固定25张A源图池逐查询核对相关性；修订动作、颜色和关系，例如把绿色栏杆上的单板动作写为滑行，去掉无法据图确认的国籍，避免把肤色词作为衣物颜色测试。B的25条已有辅助预审意见，例如号码6不是6只狗、拿冰棍不一定代表每个人都在吃。

当前状态为25条annotated、75条draft、0条reviewed；暂计多标签color53、count35、action56、relation42，其中仍含未确认初稿，不能作为已复核分布。

25图池不覆盖1000图全库或未来模型排名并集。正式测试前仍需其他成员初标、真实独立复核及共同池补审，或逐查询完整审图。`freeze-annotations`会拒绝当前工作文件。候选池评测须单独标注范围，不把未审结果当负例。

## 统一指标与比较

Recall@1/5/10定义为查询级任一相关命中率。MRR为首个相关项排名倒数的均值；Top-10只报告MRR@10，完整1000项排名才报告MRR。显式空结果按0计分并计数，缺失整个查询为输入错误。分类允许多标签重叠，空类别输出null。

E0/E1/E2使用相同冻结编码器、预处理标识、候选、查询、标注和排名深度。对比输出总体/分类表及逐查询RR变化，保留改善、退化、Top-1保持状态。bootstrap按源图片成对分组重采样，避免把同图5条描述当作5个完全独立样本；它只描述固定运行的查询变异，不能代替训练种子差异或宣布显著。

实际多种子到位后，`summarize-seeds`按相同协议、方法、编码器和深度汇总均值及样本标准差，拒绝重复种子和不同的与种子无关配置。只有1次时标准差为null。至少3个实际种子才满足计划中的多次实验目标。

D实测建库、文本编码、排序、端到端和冷启动；预热不计入稳定延迟，冷启动另列，不混合设备、规模、K、批大小与缓存状态，GPU计时须同步。分位数按`(n-1)*p`线性插值，附样本数。

## 错误分析与待填结果

自动选例按类别和改善/退化/Top-1保持状态分层，附覆盖报告和离线图片表；错误原因初始为空。真实排名到位后，A需逐图分析至少12例，四类均覆盖，成功和失败都保留，并区分文本歧义、模型错误与标注不足。

当前没有真实模型排名、训练成本或延迟实测。E0/E1/E2结果表保持待填，人工排序接口测试不纳入模型报告。数据检查及工具验收不能推导出模型已有提升。

## 复现

```bash
python -m pip install -e ".[data]"
python -m fgir prepare-a-data
python -m fgir verify-handoff --bundle data/prepared/flickr8k-v1 --data-root data
python -m fgir data-statistics --bundle data/prepared/flickr8k-v1 --output artifacts/reproduced-statistics
python -m unittest discover -s tests -v
```

实际本地验证为Python3.14.2、Pillow12.3.0；CI配置检查Python3.11，训练栈另按硬件准备，工具测试不代表PyTorch训练验证。详见[交接手册](../handoff-a.md)、[排名契约](../ranking-contract.md)和[标注指南](../annotation-guide.md)。
