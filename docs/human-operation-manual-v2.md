# research-v2 全员人工操作手册

日期：2026-10-30。适用成员：A、B、C、D对应的真实人员。目的：完成图片与文本的真实初标、交叉复核和争议处理，把导出文件交回本会话；程序合并、冻结、训练和评测由agent继续。

**发给成员：`dist/fgir-human-operation-20261030-v1.zip`。完整解压，打开 `index.html`，先读手册，再打开自己的成员任务册。无需安装Python、联网或运行训练。每位成员收到相同的完整包即可。**

## 1. 谁做哪些内容

负责人先把A/B/C/D对应到四位真实人员，填入包内 `forms/member-mapping.md`。A/B/C/D只是分工标签；页面“真实审核姓名”必须填写本人姓名。此次沿用工作文件中的分配，不重新抽样。

| 成员 | 初标val | 初标train | 初标合计 | 复核val | 复核train | 复核合计 | 复核时页面“成员”选择 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| A | 9 | 27 | 36 | 9 | 27 | 36 | B |
| B | 9 | 27 | 36 | 9 | 27 | 36 | A |
| C | 8 | 26 | 34 | 7 | 26 | 33 | D |
| D | 7 | 26 | 33 | 8 | 26 | 34 | C |

val共33组（原30组＋3组补充）、102个变体、13个组件；train共106组（原100组＋6组补充）、334个变体、39个组件。每组都要看；助手建议排除的候选也在任务内，不能直接跳过。

**页面顶部“成员”只按初标分配筛选，不会按当前姓名或审核阶段自动切换。** 例如B复核A的任务，必须选择成员A、阶段“独立复核”。任务册列出了本人初标和复核的完整sample ID、原句、候选文本、组件及中文重点问题；CSV可核对进度，不替代网页审核与JSONL导出。

val独立复核是正式门槛。本轮为便于全员统一执行，train也沿用既有复核字段安排交叉复核；不要将未完成的复核记成完成。

## 2. 按三轮执行

### 第一轮：各自初标

1. 完整解压操作包到普通文件夹，打开 `index.html` → 自己的成员任务册 → val审核页面。不要在ZIP预览窗口内直接打开HTML。
2. 顶部“成员”选自己对应的A/B/C/D。填写真实姓名，阶段选“人工初标”。先做val，再按同样步骤做train。
3. 按下一节逐组核验，填写自己的看图依据，主动选择每项判断并勾选确认，点“记录本组人工审核”。看到“已记录实际人工审核”提示后再进入下一组。
4. 每完成约3—5组，点击“导出全部 JSONL”保存备份；全部完成后再导出最终版。val和train必须分别导出。点击记录或保存只写内存，刷新、关闭网页不会保留未下载的工作。
5. 将最终文件改名，例如 `initial_A_张三_val_20261030_r01.jsonl`、`initial_A_张三_train_20261030_r01.jsonl`。日期用实际操作日期，修订用r02、r03，不覆盖他人文件。页面默认下载名可以改，文件内容和扩展名不要改。
6. 填写 `forms/submission-template.md`，将两份JSONL和提交说明的路径交回本会话。不要只发“已完成”、截图或CSV。

### 第二轮：交叉复核

1. 先等agent合并第一轮四位成员的文件，返回统一初标基线（val、train各一份）。不要导入其他人尚未合并的零散文件继续叠加；每次导入会替换页面的全部记录，可能丢失自己的内存修改。
2. 打开相应审核页面，先“导入 JSONL”导入agent返回的该划分统一初标基线。确认提示导入成功；页面应显示初标人及annotated状态。文件必须包含该划分全部33或106组，不能只截取自己的几行。
3. 按上表的“复核时页面成员选择”筛选，阶段选“独立复核”，填写自己的真实姓名。先自己看图、理解原句和变体，再参考初标意见；逐项重新判断、确认和记录。
4. 不同意初标时如实修改选择并写依据；不要为了通过而照抄。标签分歧会留在争议记录中。解析内容、归属或排除有分歧时，也在提交说明中明确列出sample ID及双方意见，不能把“页面争议数为0”当作没有这类分歧。
5. 分别导出val/train文件，例如 `review_B_李四_val_20261031_r01.jsonl`。填提交说明，交回本会话。同一人不能用两个名字完成初标和复核。

### 第三轮：争议与研究决策

1. agent合并复核文件并给出争议清单和统一基线，再交第三位真人裁决。A/B之间的争议优先交C，C/D之间的争议优先交A；具体裁决人必须不是该组初标人或已有复核人，若身份冲突由负责人另行指定。
2. 裁决人导入最新统一基线、定位争议组，阶段选“第三人争议裁决”，重新看图，说明最终依据并记录、导出。仍无法确定就保留uncertain，不强行下结论；原双方意见保留在历史中。
3. 解析修改或排除争议先由agent按真人意见整理成可审版本，再请不同真人确认。不要用裁决按钮清空争议而未实际核验。
4. 四人讨论后由实际负责人填写 `forms/research-decisions.md`：确认有效集合、覆盖与排除，是否需补样或缩小研究范围。补充val不自动替换原30组，不为凑数强造负例。

## 3. 每组到底检查什么

按“图片 → 原句 → 解析 → 每个变体 → 每个组件 → 依据与记录”的顺序操作。原句和变体保留英文原文；不能只根据中文提示或助手结论签字。

| 检查项 | 实际操作与判断标准 |
| --- | --- |
| 图片和原句 | 图片能否支持整句中的对象、数量、属性与动作？能支持选“原句被图片支持”；看不清、描述冲突或不能确认选“原句仍不确定”，写清冲突，提交时列入整组排除/待处理。原句表单没有“反驳”选项，不要为通过而选支持 |
| 对象与属性 | 对象是否来自原句？红衣属于谁、数量限定谁？不要添加原句没有提到的对象。先核对文本解析，再检查图片事实；两者都要正确 |
| 有向关系 | 检查“谁→什么动作/关系→谁”；追逐、跟随等不能只凭左右位置判断。角色身份不可区分时，交换主客可能仍然成立，不能硬判负 |
| 同义句 | 身份、数量、属性归属、关系、否定和不确定措辞全部保持。英文更顺口不等于同义，少条件或多条件要指出 |
| 最小错误编辑 | 应只改变一个语义条件，并被图片实际反驳。语义改变本身不证明错误；换成另一个仍可能成立的描述不能判反驳 |
| 真假追加 | 追加的“真”要有可见证据，“假”要有反证。同一source内、相同control_pair_id才是一对；不要跨图凑对。移除一侧后标记配对待处理，不能把剩下一侧算完整对照 |
| 英文自然性 | 每个保留变体单独选择自然、表达不自然或不确定。不要把真假和语法混为一谈；例如冠词错误会影响自然性 |
| 组件 | 检查组件原文、关联错误组件是否来自上面同一个变体、同一次编辑；对象及方向一致。组件正确不靠整句大致正确来替代 |
| 看图依据 | 写可见事实和位置/对象对应关系，并指出每个不确定或修改项。不能只写“同意助手”“通过”“已看” |

变体视觉判断的四个选项：

| 选项 | 含义 |
| --- | --- |
| 图片支持 supported | 图片有足够证据支持这句文本 |
| 图片反驳 contradicted | 图片明确与其中的条件冲突；在依据中指出冲突 |
| 不确定 uncertain | 看不清、出画、身份不明、意图无法证实等；没提到或没看见不自动等于反驳 |
| 不适用 not_applicable | 该现象不构成有效测试，例如主客不可区分；写明原因，正式发布时由agent列入排除 |

填写格式示意（不是任何真实样本的已审结论）：`原句：依据……；解析e2：属性应属于……；v-xxx：……所以不确定/反驳；u-xxx：与同次编辑一致/待修；待处理：……`。只写自己实际观察到的内容。

## 4. 错误、歧义和排除怎么处理

31组特殊问题已按实际sample ID放进成员任务册并译成中文，也有 `tasks/questions.csv`。24组原句目前仍是助手uncertain（val8、train16）；这是待人工判断清单，不是要求把它们都改成支持。

能明确判断无效的变体：先记下理由，点该变体的“移除并记录排除理由”，输入本人依据；它和关联组件会留在排除记录中。**移除会重绘当前表单、清空尚未记录的选择和意见**，因此尽量先处理需要移除的变体，再填表；若已填写，先复制自己的意见到临时文档，移除后重新核验填写。

需要改解析但不会写JSON：不用强行勾“我已检查解析”并签成完成。将sample ID、实体/关系ID、原文片段、建议改法和依据写入提交说明“待修正项”，先导出当前工作。agent修成新版本后，由本人看过修订再记录初标，另交不同真人复核。

熟悉JSON者可展开“修改解析或查看完整记录”，只改对应解析并点击“保存本组编辑”，然后重新填人工表单。不要改来源、原句、划分、分配、provenance或手写human审核字段；变体/组件引用和span由agent检查。span使用原文字符区间[start,end)，不是词序号。

整组无法使用：在原句选择不确定，写明排除建议并在提交说明列出；不要删除JSONL整行或自行改source ID。后台会另存完整排除清单。页面仍保留未审记录是正常的，不要批量把所有status改成reviewed。

## 5. 每位成员交什么

每轮val/train各一份“导出全部JSONL”，再附一份提交说明。说明至少包括：真实姓名、分工标签、阶段、输入基线文件名、已实际审核的sample ID、未审/待修正/排除/争议项、输出文件名。包内提供空白模板，不需要自己设计表格。

导出包含全部样本，即使页面只筛选本人任务也是如此；其他人的原记录保留属于正常情况。不要手工删行、拼接多份JSONL或用表格软件另存覆盖。部分完成也可以交，明确剩余项；不能把导出33行或106行说成自己审了全部。

下载后的文件通常位于浏览器“下载”目录。保留各次备份和初标/复核不同阶段文件；继续工作时先导入最新导出文件恢复。只导出一次空文件不能证明保存成功，至少确认文件非空且文件名、划分对应。

**初标完成标准**：本人分配内的每组原句、解析、每个保留变体及组件均实际核验；不确定、排除和待修明确留痕；文件已导出。**复核完成标准**：不同真人在统一初标基线上实际复核并导出；分歧进入裁决或保留待定。数据是否可冻结由agent检查与真人覆盖决策共同决定，个人交文件不等于全阶段完成。

## 6. 负责人最后确认的研究事项

当前助手建议筛选val25组/46变体、train88组/140变体，不是正式数量。建议有效绑定/方向源图仅val1/2、train2/3；88组训练正例不等于88组有效错误对照。各成员需据真实审核讨论覆盖是否足以支撑绑定、方向及消融结论。

在决策表中确认：原30组分别保留/排除/待定；3组补充val用途；最终train/val实际规模；各现象有效源图数与排除理由；是否按公开规则补样；不足时缩小哪些结论；决策人及实际日期。agent之后生成计数供核实，成员无需自己计算摘要或写冻结协议。

这一轮不操作test、不根据模型成绩挑标签、不把val放入优化器。正式test须在配置和数据冻结后另行安排真人初标/复核，并披露历史接触。正式train发布、val冻结、15组实验、正式分数与结果分析仍由agent在门槛满足后执行。

## 7. 常见问题

| 情况 | 处理 |
| --- | --- |
| 图片显示不出来 | 确认完整解压且board.html旁images目录仍在；不要单独发送HTML。仍失败就交回sample ID与文件路径，不盲审 |
| 换组或导出时提示表单尚未记录 | 先点“记录本组人工审核”；确实放弃本次输入才点“重置本组审核表单” |
| 提示初标与复核必须不同人 | 核对导入文件和阶段；必须换不同真实人员，不要换假名字绕过 |
| 导入提示样本数量或来源不一致 | 检查val/train和版本，使用agent给的完整统一基线；不要强改样本字段 |
| 误刷新或关页 | 重新打开并导入最近一次导出，之后未导出的工作需重新核验 |
| 排除后真假追加只剩一侧 | 在提交说明列出sample ID和control_pair_id，待agent处理并重新确认 |
| 不会操作或判断不了英文 | 在提交说明标记具体样本/词句与问题；不得靠复制助手结论签署 |

本手册配套的任务册和审核页提供实际操作内容；所有输入当前仍为assistant草稿，未代填任何真人姓名、审核或成绩。原始任务包与历史证据保持原样。
