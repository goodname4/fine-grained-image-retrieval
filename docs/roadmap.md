## 3. 协作接口

| 交接 | 内容 | 提供方保证 |
| --- | --- | --- |
| A→B/C/D | 固定图像划分、semantic-v1、诊断金标和排除规则 | 版本绑定、标注可审计；val与test分开 |
| B→A/C | entities/relations、同义/错误变体、原文span及核验来源 | 只改变声明条件；不把draft或uncertain作训练负例 |
| C→D/A | text-lora-v1、基础模型/LoRA结构、训练选择与数据摘要 | 可重载、冻结审计、实验编号真实 |
| D/C→A | run-v2、完整检索排名、逐项语义分数与receipt | 候选/协议一致，模型身份完整 |
| A→D/全组 | 固定结果、逐查询/源图组记录、成功失败退化案例 | 不选取单方面改善；说明相关性不完备 |

独立复核默认A/B互审、C/D互审，初标人不可充当同一记录的独立复核人；歧义由第三人或集体讨论并记录。

## 4. 阶段依赖

1. P0 A/B先完成约30组val语义试点，train候选另建。可同时由C开展不使用评测金标的可导小batch验证，D设计版本契约。
2. P1 C完成N0、LoRA重载与冻结检查；A/B冻结首版训练数据；D保持旧E0/E1/E2可用。
3. P2 C完成N1/N2及N3消融，A只用val提供诊断反馈；D完成v2制品接入。配置与选择规则冻结后才进入正式test。
4. P3 A统一执行固定test与分组统计；D联调N2/E0/N3切换、断网查询和成本测量。
5. P4各自撰写模块，D整合格式，四人共同核对引用、结果、局限与演示。

若只完成N0/N2，报告只能主张相应范围，不能声称已回答同义一致性问题。若方法无提升，保留完整对照、失败与退化分析；不替换或覆盖历史E结果。
